# Infrastructure

Terraform is the source of truth for everything EyeLecture runs on in GCP.

| | |
| --- | --- |
| Project | `eyelecture` (org `nextto.ai`, number `693861601488`) |
| Region | `us-central1` |
| State | `gs://eyelecture-tfstate`, prefix `env/prod`, versioned |

## What it creates

- **Artifact Registry** (`eyelecture`) — Docker images, with a cleanup policy so
  untagged layers don't quietly accrue storage cost.
- **Cloud SQL** — PostgreSQL 17, `db-f1-micro`, 10 GB. Postgres 17 because the
  first migration enables `pgvector`.
- **Cloud Run `eyelecture-api`** — the NestJS API.
- **Cloud Run `eyelecture-web`** — Angular served by nginx.
- **Cloud Run job `eyelecture-migrate`** — runs TypeORM migrations. Same image as
  the API, different command.
- **Secret Manager** — the database password and both JWT secrets, generated by
  Terraform and readable only by the API's runtime service account.
- **Two service accounts** — one per service, each with only what it needs. The
  web identity has no project roles at all; it only proxies HTTP.

## Applying

Terraform is applied by a human, not by CI. The GitHub Actions deploy identity
can push images and update Cloud Run services — nothing more. Granting it the
power to create databases and edit IAM would make a compromised workflow run far
more dangerous than it needs to be for a project this size.

From Cloud Shell (already authenticated):

```bash
gcloud config set project eyelecture
cd infra
terraform init
terraform plan
terraform apply
```

CI still runs `terraform fmt -check` and `terraform validate` on every PR, so
formatting and syntax errors surface before merge.

## The first apply

Cloud Run needs an image, and the image can't be built until the registry exists.
So `api_image` and `web_image` default to `gcr.io/cloudrun/hello`. The order is:

1. `terraform apply` — creates everything, with both services running the
   placeholder image.
2. Push to `main` — the deploy workflow builds the real images, runs the
   migration job, and updates both services.
3. Nothing to do on the Terraform side. The services' `image` attribute is in
   `ignore_changes`, so a later `terraform apply` will not roll them back to the
   placeholder.

## Connecting to the database

```bash
gcloud sql connect eyelecture-pg --user=eyelecture --database=eyelecture
terraform output -raw db_password   # the generated password
```

The API reaches Postgres over the Cloud SQL unix socket that Cloud Run mounts at
`/cloudsql/<connection-name>`, so `DB_HOST` is a path rather than a hostname —
`node-postgres` treats a host starting with `/` as a socket directory. This
avoids a Serverless VPC connector, which would roughly double the monthly cost
for no benefit at this size.

## Seeding the first admin

The seed script is not wired into the deploy — creating an admin account is not
something that should happen automatically on every push. Run it once, manually:

```bash
gcloud run jobs create eyelecture-seed \
  --image=us-central1-docker.pkg.dev/eyelecture/eyelecture/api:latest \
  --region=us-central1 \
  --set-cloudsql-instances="$(terraform output -raw db_connection_name)" \
  --set-secrets=DB_PASSWORD=db-password:latest \
  --set-env-vars="DB_HOST=/cloudsql/$(terraform output -raw db_connection_name),DB_PORT=5432,DB_NAME=eyelecture,DB_USERNAME=eyelecture,DB_SSL=false,SEED_ADMIN_EMAIL=you@nextto.ai,SEED_ADMIN_PASSWORD=<pick-one>" \
  --service-account=eyelecture-api@eyelecture.iam.gserviceaccount.com \
  --command=node --args=dist/database/seed.js

gcloud run jobs execute eyelecture-seed --region=us-central1 --wait
```

Change the admin password immediately afterwards, and delete the job so the
password stops living in its configuration:

```bash
gcloud run jobs delete eyelecture-seed --region=us-central1 --quiet
```

## Roughly what it costs

Idle, with `min_instances = 0`:

| Item | Monthly |
| --- | --- |
| Cloud SQL `db-f1-micro` + 10 GB HDD | ~USD 9–12 |
| Cloud Run (both services, scale to zero) | ~USD 0 at low traffic |
| Artifact Registry | ~USD 0.10 per GB |
| Secret Manager | ~USD 0.06 per secret |

The database is the only thing that bills whether or not anyone uses the app. To
stop paying while keeping the data, stop the instance:

```bash
gcloud sql instances patch eyelecture-pg --activation-policy=NEVER
```

## Tearing it down

`deletion_protection` is on for Cloud SQL, so `terraform destroy` will refuse
until you turn it off deliberately:

```bash
terraform apply -var=deletion_protection=false
terraform destroy
```
